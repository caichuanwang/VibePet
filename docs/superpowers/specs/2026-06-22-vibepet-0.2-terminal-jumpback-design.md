# VibePet 0.2 — 子项目 3：终端跳回（设计文档）

> 日期：2026-06-22
> 状态：头脑风暴产出，待用户复审
> 依赖：子项目 1（会话模型 + 全 hook）——`JumpTarget` 挂在 `AgentSession` 上，由 App 侧周期校正；本子项目排在子项目 1 之后实现。
> 参考：核心实现对齐 open-vibe-island（`TerminalJumpService` + `TerminalJumpTargetResolver`，GPL-3.0，clean-room 借鉴），并按本版终端集裁剪。

---

## 1. 目标与范围

让每个气泡可「双击跳回」到它所来自的终端窗口/tab。对 5 个终端做精确 tab/session 聚焦，其余终端走「激活 App + cwd」兜底，绝不出现「完全不能跳」。

### 成功标准（可验证）
1. 气泡（approval / question / completion / status 任一）双击 → 前台聚焦到该会话来源的终端；5 个精确终端能定位到具体 tab/session，其余至少激活对应 App 或用 cwd 兜底。
2. `JumpTarget` 在 hook 时捕获初值并随 `SourceInfo` 过桥，落到子项目 1 的 `AgentSession.jumpTarget`；App 侧 2s 轮询校正 Ghostty / Terminal.app 的精度。
3. 跳转 best-effort、fail-open：解析不到终端时降级，最终失败静默，不打断用户、不弹错误框。
4. hook 路径不跑 osascript（不在 hook 触发 macOS 自动化权限弹窗）。
5. `TerminalJumpService` 全部外部副作用经可注入闭包，单测不碰真实系统；`swift test` 通过。

### 精确定位终端集
iTerm / Terminal.app / Ghostty / cmux / VS Code。

### 非目标
- tmux / zellij / Warp（SQLite 翻 tab）/ WezTerm / Kaku / JetBrains 系（open-vibe-island 有，本版砍掉，走兜底）。
- 键盘/AX 注入（open-vibe-island 的 Warp tab-cycle 那套）。
- 网络、遥测。
- 会话模型、hook 覆盖（子项目 1）；宠物宿主 / 精灵动画（子项目 2）。

## 2. 架构（四块，对齐 open-vibe-island）

```
Hook 时捕获 ─→ JumpTarget(初值) 随 SourceInfo 过桥 ─→ AgentSession.jumpTarget (子项目1 reducer 落库)
                                                            │
App 侧 TerminalJumpTargetResolver(2s 轮询, 只探 Ghostty+Terminal) ──校正回填──┘
                                                            │
                            双击气泡 ─→ TerminalJumpService.jump(to: session.jumpTarget)
```

| 块 | 位置 | 职责 |
|---|---|---|
| `JumpTarget`（数据） | `VibePetCore`（Codable/Sendable，跨桥） | 描述一个可跳转的终端定位 |
| Hook 捕获 | `VibePetCore` adapter（`parseEvent(stdin:env:)` 已有 `env`） | 组装 `JumpTarget` 初值 |
| `TerminalJumpTargetResolver`（校正） | `VibePetApp`（AppKit/osascript） | 2s 轮询会话列表，AppleScript 校正 Ghostty/Terminal |
| `TerminalJumpService`（跳转） | `VibePetApp`（AppKit/osascript/socket/CLI） | 按终端类型分派聚焦 |

> **裁剪带来的简化**：本版精确集裁到 5 个后，**App 侧轮询校正只需探 Ghostty + Terminal.app**——iTerm 的 sessionID 来自 `ITERM_SESSION_ID`、cmux 来自 `CMUX_SURFACE_ID`、VS Code 只用 cwd，三者在 hook 当场抓全，无需 App 侧反复校正。故轮询层显著轻于 open-vibe-island。

## 3. 数据模型 `JumpTarget`（Core）

裁剪 open-vibe-island 版，只留 5 终端所需字段：

```
struct JumpTarget: Codable, Equatable, Sendable {
    var terminalApp: String          // "iTerm"/"Terminal"/"Ghostty"/"cmux"/"VS Code"/"Unknown"
    var workspaceName: String        // cwd lastPathComponent，兜底显示/打开用
    var paneTitle: String
    var workingDirectory: String?
    var terminalSessionID: String?   // iTerm: ITERM_SESSION_ID; cmux: CMUX_SURFACE_ID; Ghostty: 校正回填
    var terminalTTY: String?
}
```

- 砍掉 open-vibe-island 的 `tmuxTarget` / `tmuxSocketPath` / `warpPaneUUID` / `codexThreadID`。
- `SourceInfo` 增加 `jumpTarget: JumpTarget?`（`decodeIfPresent`，旧包/缺字段解码为 `nil`，向后兼容）。
- 真值落点：子项目 1 的 `AgentSession.jumpTarget`（与 open-vibe-island 同构）；envelope 携带的是初值，reducer 落库后由 §5 校正。

## 4. Hook 时捕获（Core，廉价、fail-open）

adapter 的 `parseEvent(stdin:env:)` 已有 `env: [String: String]`（hook 进程继承终端环境）。在 `makeSource` 链路里组装 `JumpTarget` 初值。移植并裁剪 open-vibe-island 的两个原语：

- **`inferTerminalApp(from: env)`**：
  - `CMUX_WORKSPACE_ID` / `CMUX_SOCKET_PATH` → `"cmux"`（多路复用优先）。
  - `TERM_PROGRAM`（权威信号）：`apple_terminal`→`Terminal`、`iterm.app`/`iterm2`→`iTerm`、含 `ghostty`→`Ghostty`、`vscode`→`VS Code`（Cursor 也设 `vscode`，本版不单独区分，统归 `VS Code`）。
  - 兜底（`TERM_PROGRAM` 为空时）：`ITERM_SESSION_ID`/`LC_TERMINAL==iTerm2`→`iTerm`、`GHOSTTY_RESOURCES_DIR`→`Ghostty`。
  - 都不命中 → `"Unknown"`。
- **`currentTTY()`**：`/usr/bin/tty`，失败回退 `ps -p <ppid> -o tty=`，规整为 `/dev/...`。
- **sessionID**：iTerm 取 `ITERM_SESSION_ID`；cmux 取 `CMUX_SURFACE_ID`。
- **cwd**：复用现有 `SourceInfo.cwd`；`workspaceName` = `cwd` 的 `lastPathComponent`。

**有意偏移 open-vibe-island**：不在 hook 跑 osascript（open-vibe-island 对部分终端有 hook 时的 `terminalLocator` / focused-terminal locator）。改由 §5 的 2s 轮询补 Ghostty/Terminal 精度。收益：hook 路径快、不在 hook 触发自动化权限弹窗、保持 fail-open。代价：Ghostty/Terminal 的精确 sessionID/tty 要等首次轮询补齐（≤2s），对用户双击时机无实感影响。

## 5. App 侧 `TerminalJumpTargetResolver`（2s 轮询，只探 2 个终端）

移植 open-vibe-island 的 Ghostty + Terminal.app 部分：

- `fetchGhosttySnapshots()` / `fetchTerminalSnapshots()`：osascript 枚举活终端（Ghostty 取 id/cwd/title；Terminal 取 tty/custom title），3s 超时、失败返回空。
- 三级匹配（沿用 open-vibe-island）：Ghostty 走 sessionID → cwd → title；Terminal 走 tty → title。命中则回填/校正会话的 `terminalSessionID` / `terminalTTY` / `paneTitle` / `workspaceName`。
- **iTerm / cmux / VS Code 不参与校正**（hook 已抓全）→ 轮询跳过，省 AppleScript 开销。
- 挂在子项目 1 的会话监控循环里（每 2s 跑一次，对 live 会话列表）；纯校正，绝不影响会话可见性/存活判定，绝不阻塞主线程。

> 依赖说明：本层入参是会话列表（子项目 1 的 `SessionState.sessions`）。子项目 1 未落地前本层无法启用——这是本子项目排在其后的根本原因。

## 6. `TerminalJumpService.jump(to:)`（App）

裁剪 open-vibe-island 的分派，只留 5 条 + 兜底链。所有外部副作用走可注入闭包（`openAction` / `appleScriptRunner` / `processRunner` / socket）。

| 终端 | 机制 | 复用 open-vibe-island |
|---|---|---|
| iTerm | AppleScript 按 sessionID/tty 选中 window/tab/session | `jumpToITermSession` |
| Terminal.app | AppleScript 按 tty/custom title 选中 tab | `jumpToTerminalTab` |
| Ghostty | AppleScript 按 sessionID/cwd/title 聚焦 terminal | `jumpToGhosttyTerminal` |
| cmux | Unix socket JSON-RPC `surface.focus`（`CMUX_SURFACE_ID`） | `jumpToCmuxTerminal` + socket 路径解析 |
| VS Code | CLI `code -r <cwd>` 聚焦工作区窗口 | VS Code family CLI 分支（裁到单一 `code`） |

**兜底链**（任一精确分支未命中时）：`open -b <bundleID>` 激活 App → `open <cwd>`（Finder 打开目录）→ 抛 `TerminalJumpError.unsupportedTerminal`。`terminalApp == "Unknown"` 直接进兜底链。

## 7. 双击交互（App）

- 在气泡/卡片 body 加 `onTapGesture(count: 2)` → 调 `TerminalJumpService.jump(to: source.jumpTarget)`。`source` 已由 `PetController` / `PetSurface` 透传到每张卡片（`presentBubble` / `presentApproval` / `presentQuestion` 都带 `source:`），无需新增管线。
- 单击维持原状：approval/question 的允许/拒绝/提交按钮、bubble 关闭。双击只作用于卡片背景，不与按钮抢手势。
- 全部气泡类型可双击跳回（都带 `source`）。
- 无 `jumpTarget`（旧包 / `Unknown` 且无 cwd）→ 双击无操作（或极轻提示），不弹错误框。

---

## 8. Fail-open / 权限

- 跳转 best-effort：解析不到终端 → 降级激活/打开 cwd → 最终失败静默（双击场景不打断用户）。
- AppleScript 首次触发 macOS 自动化权限弹窗——在设置页/onboarding 给一句说明（可后续补，不阻塞本版核心）。
- `TerminalJumpService` 与 `TerminalJumpTargetResolver` 的 open/osascript/socket/CLI 全部经注入闭包 → 单测不碰真实系统。
- 与既有护栏一致：App 未运行 / socket 失败 / 输入异常时，跳回能力缺失不影响 Claude/Codex 原生流。

## 9. 测试与验证

- **`JumpTarget` 编解码** + `SourceInfo` 向后兼容（旧包无 `jumpTarget` → `nil`）。
- **`inferTerminalApp`**：各 `env` 组合表驱动单测（cmux / TERM_PROGRAM 各值 / 兜底 env / Unknown）。
- **`currentTTY`**：`/usr/bin/tty` 成功路径 + `ps` 回退路径（注入命令输出）。
- **resolver 匹配**：注入假 AppleScript 输出，Ghostty/Terminal 快照 × 会话 → 期望回填；iTerm/cmux/VS Code 不被校正。
- **`jump(to:)` 分派**：每种终端 × 注入闭包 → 断言调用了正确的 open/osascript/socket/CLI 参数与兜底链顺序；`Unknown` 直接兜底。
- **双击**：在 controller/卡片层验证双击调用 `jump` 恰一次。
- 注意：写入仍可能命中真实系统，**仅单测、不做真实冒烟**；`swift test` 偶发 SIGPIPE 非回归。

## 10. 决策与约束记录

- **Decided**：方案 B，对齐 open-vibe-island（App 侧 2s 轮询校正 + 持久会话列表），依赖子项目 1。
- **Decided**：精确定位终端 = iTerm / Terminal.app / Ghostty / cmux / VS Code；其余走「激活 App + cwd」兜底。
- **Decided**：交互 = 双击气泡 body；全部气泡类型可跳。
- **Decided（偏移 open-vibe-island）**：不在 hook 跑 osascript（focused-terminal locator 移到 App 侧 2s 轮询）；不做 tmux/zellij/Warp/WezTerm/Kaku/JetBrains；Cursor 暂归 VS Code 不单独区分。
- **Constraint**：`JumpTarget` 数据在 `VibePetCore`；`TerminalJumpService` / `TerminalJumpTargetResolver` 在 `VibePetApp`（AppKit/osascript/socket/CLI）。`VibePetCore` 不引入 AppKit/SwiftUI。
- **Constraint**：fail-open——跳回能力任何环节失败都不得影响既有桥接/hook 原生流。
- **依赖**：`AgentSession.jumpTarget` 与会话监控循环来自子项目 1；子项目 1 未落地前，App 侧校正层与落库无法启用。
