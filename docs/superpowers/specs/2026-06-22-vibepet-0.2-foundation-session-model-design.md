## 0. 0.2 整体蓝图与已定决策（背景，非本文实现范围）

本文只实现"地基块"，但记录 0.2 的整体方向与已拍板决策，供下游文档与实现对齐。

### 0.1 产品方向转变（已定）
- **砍掉照片抠图**：退役本地抠图生成管线，VibePet 转型为 **Codex 宠物（spritesheet 格式）桌面宿主**。
- **差异化重心转移**：不再靠"你的照片"，而靠**最深的交互式 agent 集成**——在桌面气泡里真实 allow/deny + 答多选题，横跨 Claude Code + Codex，配合整个 Codex 宠物市场。
- **宠物来源（已定）**：读共享 `~/.codex/pets/`（原地引用、实时同步）+ 拖拽导入宠物文件夹 + App 自带默认宠物；纯本地，**不引入网络**；App 内画廊浏览留待后续版本。

### 0.2 子项目分解与顺序（已定）
1. **地基块：会话模型 + 全 hook 生命周期**（← 本文）。其余子项目的共同依赖。
2. **宠物模型转型 + 精灵动画**：砍抠图、接 Codex spritesheet、约 5 个动画行接满会话 phase。**"砍掉抠图"在子项目 2 落地**（精灵渲染器就位时一起删，避免桌面空窗）——故本子项目（1）期间抠图渲染器暂留作占位。
3. **终端跳回**：审批/完成气泡加"跳回来源终端"按钮，复用本文产出的 `JumpTarget`（取子集）。

### 0.3 关键事实（调研结论）
- Codex 宠物 = `~/.codex/pets/<slug>/` 下 `pet.json` + spritesheet（8 列 × 9 行、单元格 192×208、整图 1536×1872），**9 行 = 9 个动画状态**，按 agent 活动组织。
- petdex sidecar 公开的事件→状态映射：`tool.before→running`、`tool.after→idle`、`session.end→waving`、`session.error→failed`。
- **关键洞察**：十几个生命周期 hook 并不是十几个状态——它们大多只更新 summary/metadata，真正的会话 phase 收敛到 **4 个**。宠物动画因此只需约 5 行。

## 1. 本子项目目标与成功标准

### 目标
在 VibePet **现有双通道 bridge 之上**，新增一层**持久多会话 `SessionState` reducer**，并**拓宽 hook 生命周期覆盖**，使宠物能反映"持续态"（正在跑工具 / 待审批 / 待答题 / 完成 / 失败 / 待机）与多会话，而不只是一事件一气泡。

### 成功标准（可验证）
1. 给定一串 `AgentEvent` 序列，`SessionState.apply` 产出确定的 `[sessionID: AgentSession]`（纯函数、单测覆盖）。
2. 现有审批/提问的**阻塞决策回路行为不变**（allow/deny/答题仍同步回传工具，fail-open 不退化）；决策的开始/结束**同时**更新会话 phase。
3. Claude 注册并正确解析全部目标生命周期 hook（见 §4），Codex 注册并解析 SessionStart/UserPromptSubmit（叠加现有 PermissionRequest/Stop）。
4. 菜单栏可见多会话聚合：活跃会话数、需关注（待审批/待答题）数。
5. fail-open 鲁棒：App 未运行/连接失败/SessionEnd 不到达时，hook 不阻塞工具；"卡住可见"的会话经进程探活兜底清理。
6. 安装器对新增 hook 保持**幂等 / manifest 记录 / 自动备份 / 精确卸载**；hook 命令路径正确单引号转义（稳定安装路径含空格）。

### 非目标（本子项目不做）
- 精灵渲染、Codex 宠物接入、抠图删除（→ 子项目 2）。
- 终端跳回 UI 与多终端解析（→ 子项目 3；本文只产出 `JumpTarget` 数据结构与采集占位）。
- 会话状态跨 App 重启持久化（本文仅内存态）。
- Cursor/Gemini 等更多工具（保持 MVP 的 Claude Code + Codex）。

## 2. 架构总览

```
                    现有（不改机制）                         新增（本子项目）
  ┌──────────┐  decision (阻塞)   ┌───────────────┐   apply(event)   ┌────────────────┐
  │ Hook CLI │ ─────────────────▶ │ BridgeServer  │ ───────────────▶ │  SessionState  │
  │(VibePet  │  notification(单向) │ Host          │                  │  reducer       │
  │ Hooks)   │ ─────────────────▶ │ (decide/notify│ ◀─ resolve ───── │ [id: Session]  │
  └──────────┘                    │  streams)     │  Permission/      └───────┬────────┘
       ▲                          └───────────────┘  answerQuestion           │ 派生
       │ 各工具 hook 事件                                                       ▼
  Claude Code / Codex                                              PetActivity + 菜单栏聚合
```

- **不改**：Unix socket、`HookRuntime.runDecision/runNotification`、`BridgeServerHost` 的 `decideStream/notifyStream`、按 `requestId` 配对回传、20s 倒计时 fail-open。
- **新增**：`SessionState` 作为 App 侧**单一事实源**，由两条通道共同喂养：
  - 通知 envelope → 翻译成 `AgentEvent` → `apply`。
  - 决策 envelope → 进入阻塞回路时置会话 `waitingForApproval/Answer`；用户 resolve → `resolvePermission`/`answerQuestion` 置回 `running/completed`。
- 宠物当前活动与菜单栏数字由 `SessionState` **派生**，不再由单个 envelope 直接决定。

`SessionState` 放在 Core（UI 无关、纯值类型，便于单测）；其持有与变更在 App 侧由一个 actor/main-actor 协调器封装（复用 `BridgeServerHost`/`PetController` 现有 actor 边界）。

## 3. 1a — 会话模型（clean-room）

### 3.1 类型（草案，置于 `VibePetCore/Session/`）

```
enum SessionPhase: String, Codable, Sendable, CaseIterable {
    case running, waitingForApproval, waitingForAnswer, completed
    var requiresAttention: Bool { self == .waitingForApproval || self == .waitingForAnswer }
}

struct AgentSession: Equatable, Sendable, Codable {
    let id: String                 // 稳定 sessionID（见 §3.4）
    var title: String
    let tool: ToolKind             // 复用现有 ToolKind（claudeCode/codex）
    var phase: SessionPhase
    var summary: String
    var updatedAt: Date
    var firstSeenAt: Date
    var jumpTarget: JumpTarget?    // 数据结构本文产出，采集留给子项目 3
    // fail-open 探活
    var isSessionEnded: Bool
    var isProcessAlive: Bool
    var processNotSeenCount: Int
    var isVisible: Bool { /* requiresAttention || (!isSessionEnded && isProcessAlive) || 近期完成 */ }
}

struct SessionState: Equatable, Sendable {
    private(set) var sessionsByID: [String: AgentSession]
    mutating func apply(_ event: AgentEvent)
    mutating func resolvePermission(sessionID:, approved: Bool, at:)
    mutating func answerQuestion(sessionID:, summary: String, at:)
    @discardableResult mutating func markProcessLiveness(aliveSessionIDs: Set<String>) -> Set<String>
    // 派生：activeActionableSession / runningCount / attentionCount / visibleSessions
}
```

> `JumpTarget`（子集，本文仅定义并随事件透传，不实现解析）：
> `terminalApp, workspaceName?, paneTitle?, workingDirectory?, terminalTTY?, codexThreadID?`。

### 3.2 事件词汇 `AgentEvent`
带 `type` 标签的 sum type，每个 case 携带 `sessionID` + `timestamp`：

| 事件 | 触发来源（示例） | reducer 语义 |
|---|---|---|
| `sessionStarted` | SessionStart | upsert 会话，phase=running，置打招呼标记；保留已存在的 firstSeenAt |
| `activityUpdated` | UserPromptSubmit / PreToolUse / PostToolUse / SubagentStart-Stop / PreCompact / Notification | 更新 phase(running)+summary；**不**覆盖正待决策的会话 |
| `permissionRequested` | PreToolUse(决策) / PermissionRequest | phase=waitingForApproval，存 preview |
| `questionAsked` | AskUserQuestion | phase=waitingForAnswer，存题干 |
| `sessionCompleted` | Stop / StopFailure / SessionEnd | phase=completed；`isError`(StopFailure) / `isSessionEnd`(SessionEnd) 标记 |
| `jumpTargetUpdated` | 任意带终端信息的 hook | 更新 jumpTarget |
| `actionableStateResolved` | 用户在终端自行处理后 | 仅当处于 waiting* 时清回 running |

reducer 关键不变量（借鉴自参考实现的思路，clean-room 重写）：
- `activityUpdated` 若会话正 `waitingForApproval/Answer` 且仍有未决请求，则**不降级** phase（避免并发事件把待决策态冲掉）。
- 未知 `sessionID` 的非 `sessionStarted` 事件：忽略（容错）。

### 3.3 决策通道与会话状态的衔接
- 决策 envelope 到达 → 在挂起阻塞回路前，向 reducer 投 `permissionRequested`/`questionAsked`（phase 进入 waiting）。
- 用户在气泡点击 → 现有回传机制不变 + 调 `resolvePermission(approved:)`/`answerQuestion(summary:)`：approved/答题 → running；deny → completed。
- 超时 fail-open（无响应）→ 视作 `actionableStateResolved`（回 running，交还原生流程），不改变"hook 不阻塞工具"的既有行为。

### 3.4 稳定 `sessionID`（实现期要钉）
现有 `SourceInfo` 只有 `sessionShortId`。reducer 需要**跨事件稳定**的 id：
- Claude：hook payload 的 `session_id`。
- Codex：会话/线程标识（payload 提供的 session/thread id）。
- 落地：`SourceInfo` 增补 `sessionID: String`（adapter 填充）；`sessionShortId` 保留作展示。

### 3.5 fail-open 探活
- App 周期性枚举存活的 agent 进程，`markProcessLiveness`：连续 2 次未见且非 `sessionStarted/活跃` → 标记 ended、phase=completed、从可见集移除。
- 兜底"SessionEnd 永不到达"（bridge 中断、进程被杀）导致的"卡住可见"。

### 3.6 对外派生
- `PetActivity`（现有枚举，本文暂沿用 idle/greeting/deciding）由聚合派生：有 `requiresAttention` 会话 → `deciding`；否则有 running → （暂映射 idle，running 行留给子项目 2）；sessionStarted → greeting 一次。
- 菜单栏：展示 `visibleSessions` 数与 `attentionCount`。

## 4. 1b — 全 hook 生命周期覆盖

### 4.1 目标覆盖
- **Claude Code**：现有 `PreToolUse / Stop / Notification` + 新增 `SessionStart / UserPromptSubmit / PostToolUse / SubagentStart / SubagentStop / SessionEnd / StopFailure / PermissionDenied / PreCompact`。
- **Codex**：现有 `PermissionRequest / Stop` + 新增 `SessionStart / UserPromptSubmit`。
- **阻塞 vs 通知**：仅 `PreToolUse`(决策) / `PermissionRequest` /（如启用）`AskUserQuestion` 走**阻塞决策通道**；其余全部 **fire-and-forget 通知**。

### 4.2 适配层（`ClaudeCodeAdapter` / `CodexAdapter`）
- 每个 hook payload → 对应 `AgentEvent`（见 §3.2 映射表）。
- 解析**容错 fail-open**：字段缺失/未知事件 → 记录可读兜底并丢弃，绝不抛错阻塞工具。
- 摘要兜底：payload 不含可展示摘要时用可读文案（如"这轮任务已结束"），不把 Markdown 摘要作硬依赖（PRD §5.1）。

### 4.3 安装器（`ClaudeCodeConfigWriter` / `CodexConfigWriter` / `HookInstaller` / `InstallManifest`）
- 注册新增 hook 条目，复用现有：**幂等**、**manifest 记录条目+二进制版本**、**写前展示+确认+自动备份**、**精确卸载**。
- hook 命令路径**单引号转义**（稳定安装路径 `~/Library/Application Support/VibePet/bin/VibePetHooks` 含空格，经 `/bin/sh -c`）。
- Codex 新增 hook 若触发 review/trust：安装态标"待信任"，引导用户在 Codex `/hooks` 确认；未信任前不宣称生效。
- 多来源 hook 并发：回写按幂等、可并发设计，不假设独占。

## 5. 数据流（端到端示例：一次工具调用）

1. Claude `SessionStart` → 通知 → `sessionStarted` → 会话 running，宠物打招呼。
2. `UserPromptSubmit` → `activityUpdated(running)`。
3. `PreToolUse`（决策）→ `permissionRequested` → phase=waitingForApproval，宠物 `deciding` + 审批气泡（阻塞）。
4. 用户点"允许" → 现有回传 allow + `resolvePermission(approved:true)` → running。
5. `PostToolUse` → `activityUpdated(running)`。
6. `Stop` → `sessionCompleted` → completed，完成气泡（非阻塞）。
7. 若改为 `StopFailure` → `sessionCompleted(isError)` → 失败提示。

## 6. 错误处理与 fail-open（不可回退的红线）
- App 未运行 / socket 失败 / 输入畸形 / 超时 → hook ≤ 2s 退出、回退原生流程（既有行为，**不得退化**）。
- reducer 容错：未知会话/事件忽略；解析失败丢弃不抛。
- 探活兜底清理"卡住可见"会话。
- 工具 hook timeout 必须 > VibePet 倒计时。

## 7. 测试与验证
- **reducer 单测**：事件序列 → 期望 `SessionState`（含并发待决策不被冲掉、未知会话忽略、completed/ended 可见性、resolve/answer 转移、探活清理）。
- **adapter 解析单测**：每个新 hook 的 fixture payload → 期望 `AgentEvent`；畸形/缺字段 → fail-open。
- **安装器单测**：新增条目幂等、manifest 往返、卸载精确移除、路径单引号转义。**仅单测，不做真实安装冒烟**（写入会命中真实 `~/.claude`/`~/.codex`，即便覆盖 `$HOME`）。
- **回归**：现有 M4 审批 / M5 提问阻塞回路与 fail-open 行为不变。
- 注意 `swift test` 偶发 SIGPIPE（signal 13）非回归，可重跑或 `--filter`。

## 9. 决策与约束记录
- **Constraint**：保持现有阻塞决策回路与 fail-open 不退化；`VibePetCore` 不引入 AppKit/SwiftUI；纯本地、无网络/遥测。
- **Constraint**：open-vibe-island 为 GPL-3.0，仅 clean-room 借鉴架构，不复用源码。
- **Rejected（轻量版 Y）**：保留无状态 bridge、仅把新 hook 映射成一次性气泡。原因：宠物动画行是持续态，无状态撑不住"running 直到 PostToolUse"，且无多会话/跳回基础。
- **Rejected（拷贝隔离共享宠物）**：共享 Codex 宠物改为原地引用，实时同步、不占空间（属子项目 2，记此以免回退）。
- **分阶段**：1a 先用现有 4 类事件接通会话模型，1b 再铺开全 hook 点亮 running 等持续态——避免一次性大爆炸。
